**Prolog** (от _PROgramming in LOGic_) — это язык **логического программирования**, созданный в 1972 году Аленом Кольмероэ и Филиппом Русселем. В отличие от привычных языков (Python, C, Java), где программа — это **последовательность инструкций**, которые нужно выполнить, программа на Prolog — это **набор фактов и правил**, описывающих некоторую предметную область, и **вопросов** к этой базе знаний. Исполнитель (Prolog-движок) сам находит ответ, перебирая возможные подстановки переменных и применяя правила логического вывода. Prolog основан на **исчислении предикатов первого порядка** (формальной логике) и на механизме **унификации** — сопоставления термов — с автоматическим откатом (**backtracking** - возвратом при неудаче). Prolog широко применяется в экспертных системах, обработке естественного языка, автоматическом доказательстве теорем, планировании и — в последние годы — в нейро-символических системах, где логический вывод сочетается с нейросетевыми моделями. PyAgentProlog — современная реализация этой парадигмы на Python, дополненная агентами, трассировкой, семантической унификацией и .

## Часть I. Декларативное программирование

### 1. Постановка задачи: база знаний о семье

Прежде чем говорить о декларативном программировании, определим **задачу** и **данные**.

У нас есть база знаний о семье — кто чей родитель. Пусть она хранится как список пар `(родитель, ребёнок)`:

```python
family = [
    ("ivan",   "alexey"),
    ("ivan",   "maria"),
    ("alexey", "petr"),
    ("alexey", "anna"),
    ("maria",  "sergey"),
]
```

Что означает эта структура данных:

- Каждая пара `(a, b)` — это **один факт**: `a` — родитель `b`.
- `("ivan", "alexey")` читается: *«Иван — родитель Алексея»*.
- `("alexey", "petr")` — *«Алексей — родитель Петра»*.
- Первый элемент пары — **родитель**, второй — **ребёнок**.
- Порядок пар в списке не важен, важно только их содержимое.

По этим данным мы можем ответить на вопросы:
- Кто дети Ивана? → `alexey`, `maria`.
- Кто родители Петра? → `alexey`.
- Кто **внуки** Ивана? → дети его детей → `petr`, `anna`, `sergey`.

Последний вопрос — **цель нашей задачи**: найти всех внуков Ивана.

Визуально это генеалогическое дерево:

```
       ivan
      /    \
   alexey  maria
   /   \      \
 petr  anna  sergey
```

Внуки Ивана — это `petr`, `anna`, `sergey` — все узлы на **втором** уровне ниже Ивана.

### 2. Императивное решение: как это сделать на Python

Попробуем решить задачу привычным способом — через циклы.

**Идея алгоритма:**

1. Пройти по всем парам и найти детей Ивана (прямых потомков).
2. Для каждого ребёнка — снова пройти по всем парам и найти **его** детей.
3. Собрать результаты в список.

**Код:**

```python
def find_grandchildren(parents, person):
    result = []
    # Шаг 1: найти всех детей person
    children = []
    for (p, c) in parents:
        if p == person:
            children.append(c)
    # Шаг 2: для каждого ребёнка найти его детей
    for child in children:
        for (p, c) in parents:
            if p == child:
                result.append(c)
    return result

print(find_grandchildren(family, "ivan"))
# ['petr', 'anna', 'sergey']
```

**Что здесь важно понять:**

- Мы **явно описываем шаги**: «сначала найди детей, потом для каждого — внуков».
- Внешний цикл проходит по `children` (список прямых детей).
- Внутренний цикл проходит по **всему** списку `parents` для каждого ребёнка.
- Сложность — **O(N × M)**, где N — число прямых детей, M — общий размер базы. На 1000 фактов и 3 детях — 3000 итераций.

**Слабости этого решения:**

1. **Хрупкость.** Если данные придут в другом формате — например, `{"parent": "ivan", "child": "alexey"}` (словари вместо пар) — **всю функцию придётся переписывать**.
2. **Повторение.** Логика «найти детей X» дублируется дважды — во внешнем и во внутреннем цикле. Если появится третье условие (например, «только дети старше 18»), код снова вырастет.
3. **Масштабирование.** Хотите правнуков? Нужен **третий** вложенный цикл:
   ```python
   for child in children:
       for grandchild in get_children(parents, child):
           for great_grandchild in get_children(parents, grandchild):
               result.append(great_grandchild)
   ```
   Каждый новый уровень — новый цикл. Хотите «все потомки на любую глубину» — уже нужна рекурсивная функция, которая на каждом шаге делает ту же работу.
4. **Индексы.** Чтобы найти детей `child`, вы каждый раз проходите по **всему** списку `family`. Если фактов миллион — это дорого.

Всё это — цена того, что вы описываете **как** искать, а не **что** искать.

### 3. Декларативное решение: что мы ищем

Теперь опишем ту же задачу декларативно. В Prolog **данные** — это факты:

```prolog
parent(ivan, alexey).
parent(ivan, maria).
parent(alexey, petr).
parent(alexey, anna).
parent(maria, sergey).
```

Каждый факт `parent(a, b)` — ровно то же самое, что пара `(a, b)` в Python-списке: *«a — родитель b»*.

А теперь — правило для внуков:

```prolog
grandparent(X, Z) :-
    parent(X, Y),
    parent(Y, Z).
```

Читается как **определение**:

> *«X — дедушка/бабушка Z, **ЕСЛИ** X — родитель Y **И** Y — родитель Z»*.

Сравните с императивным решением:
- **Никаких циклов.** Мы не говорим «пройди по списку, найди, повтори».
- **Никаких индексов, длин списков, условий выхода.**
- **Никаких функций `get_children`.** Логика «найти детей X» — это просто `parent(X, Y)`, встроенное унификацией.
- **Одно правило описывает все случаи** — для одного факта, для тысячи, для пустой базы.

**Запрос:**

```prolog
?- grandparent(ivan, X).
```

Prolog сам находит все решения и возвращает:

```
X = petr ;
X = anna ;
X = sergey.
```

### 4. Что делает Prolog-движок

Когда вы задаёте `grandparent(ivan, X)`, движок **ищет доказательство**:

1. **Сопоставление с правилом.** Находит правило `grandparent(X, Z) :- parent(X, Y), parent(Y, Z)`. Унифицирует голову правила с запросом: переменная `X` правила становится `ivan`, переменная `Z` — переменной `X` из запроса (обе пока не связаны).

2. **Первая цель:** `parent(ivan, Y)`. Ищет факты с `parent(ivan, ...)`:
   - `parent(ivan, alexey)` → `Y = alexey`.
   - Сохраняет точку выбора: «если не получится, взять `maria`».

3. **Вторая цель:** `parent(alexey, Z)`. Ищет факты с `parent(alexey, ...)`:
   - `parent(alexey, petr)` → `Z = petr`. **Успех.**
   - Сохраняет точку выбора: «если попросят ещё — взять `anna`».

4. **Возврат первого решения:** `X = petr`.

5. **Пользователь просит «ещё»** (▶ Run находит все, ⏩ First — только первое):
   - Движок возвращается к последней точке выбора в `parent(alexey, Z)` и берёт `anna` → `X = anna`.
   - Ещё раз → `Z = petr`, `anna` закончились, возвращается к `parent(ivan, Y)` → берёт `maria` → `parent(maria, sergey)` → `X = sergey`.
   - Ещё раз → всё закончилось, ответ `false` (или «нет решений»).

**Ключевой момент:** движок сам делает всё, что в Python было циклами, списками и проверками. Вы описали **что** означает быть внуком, движок нашёл **все** подходящие значения.

### 5. Сравнение на одной задаче

| Аспект | Императивно (Python) | Декларативно (Prolog) |
|---|---|---|
| Данные | `family = [(a,b), ...]` | `parent(a, b).` |
| Логика | 2 вложенных цикла | `grandparent(X,Z) :- parent(X,Y), parent(Y,Z).` |
| Найти детей X | Отдельная функция или цикл | Просто цель `parent(X, Y)` |
| Масштабирование (правнуки) | +1 цикл | +1 правило |
| Масштабирование (все потомки) | Рекурсивная функция + ручной стек | `descendant(X,Z) :- parent(X,Z).` <br> `descendant(X,Z) :- parent(X,Y), descendant(Y,Z).` |
| Хрупкость к формату данных | Высокая | Формат — сам синтаксис фактов |
| Производительность на 1000 фактов | O(N) проходов | Индекс по первому аргументу — O(1) для `parent(ivan, Y)` |

Правило для «всех потомков» на Prolog:

```prolog
descendant(X, Y) :- parent(X, Y).
descendant(X, Y) :- parent(X, Z), descendant(Z, Y).
```

Оно находит **любого** потомка, на **любой** глубине — без единого цикла. Попробуйте написать то же самое на Python без рекурсии — получится 10–15 строк с ручным стеком и проверкой циклов (иначе уйдёт в бесконечность на графе с петлёй).

### 6. Почему это возможно: унификация вместо присваивания

Корень различия — в том, что в Prolog **нет присваивания**. Есть только **унификация** — операция «сделать два терма одинаковыми, найдя подстановку переменных».

Рассмотрим императивное присваивание:

```python
y = alexey           # y теперь равен alexey
y = maria            # y теперь равен maria (старое значение потеряно)
```

В Prolog:

```prolog
Y = alexey,          % Y связана с alexey
Y = maria.           % попытка связать Y с maria → провал
```

`Y` — **не ячейка памяти**, а переменная логики. Она может быть связана **один раз** — и остаётся связанной до конца доказательства. Нельзя «перезаписать» — можно только **откатиться** (backtracking), чтобы попробовать другое значение.

Именно поэтому `parent(X, Y), parent(Y, Z)` работает как «естественное» описание: `Y` — это **общий** ребёнок для двух целей, и унификация гарантирует, что оба вызова `parent` согласованы.

В императивном коде то же самое делается **вручную**: в промежуточной переменной, в проверках, в циклах. В Prolog эта согласованность — **встроена в язык**.

### 7. Что это даёт на практике

Три вещи, которые вы получите, думая декларативно:

**Меньше кода.** Правило `grandparent` — 3 строки. Python-эквивалент — 8 строк, и он растёт с каждым новым отношением.

**Меньше ошибок.** Нет циклов — нет off-by-one, нет «забыл проверить пустой список», нет «порядок аргументов перепутан». Ошибки возможны в самой **логике** — но они видны прямо в тексте правила.

**Естественная реляционность.** Одно и то же правило работает в **разных режимах**:

```prolog
?- grandparent(ivan, X).      % кто внуки Ивана?
?- grandparent(X, petr).      % кто дедушки/бабушки Петра?
?- grandparent(ivan, petr).   % Иван — дедушка Петра? (true/false)
?- findall(X-Z, grandparent(X, Z), L).  % все пары дедушка-внук
```

Императивная функция `find_grandchildren(parents, person)` работает **только** в первом режиме. Чтобы получить «кто дедушки Петра», нужна **другая** функция. В Prolog — та же самая.

### 8. Пределы декларативности

Не всё так радужно. Обратная сторона:

**Порядок целей важен.** `parent(X, Y), parent(Y, Z)` и `parent(Y, Z), parent(X, Y)` дадут разные результаты по эффективности, а иногда и по корректности (если одна из целей уходит в бесконечность). Prolog выполняет цели **слева направо** — вы должны думать о порядке.

**Бесконечная рекурсия — реальная проблема.** `loop :- loop.` — программа, которая никогда не завершится. В императивном коде такой баг поймали бы «зависание», здесь — тоже, но без явного стека вызовов.

**Производительность требует понимания.** `assert`/`retract` перестраивают индекс. `findall` собирает **все** решения в память. Порядок правил влияет на порядок решений. Индекс по первому аргументу работает только для **констант**.

**Отсечение `!` — не декларативно.** Это императивный «стоп», и его нужно применять осознанно.

Но эти ограничения — **детали**, которые приходят с опытом. Главное — **сдвиг мышления**: вы описываете **что** истинно, а не **как** это вычислить. Prolog берёт на себя перебор, унификацию и backtracking.

Именно поэтому декларативный подход хорошо ложится на задачи, где важно **описание** (экспертные системы, онтологии, обработка естественного языка, модели мира у агентов, планирование), а не **алгоритм** (числодробилки, обработка потоков).

В следующих разделах мы разберём синтаксис Prolog, рекурсию, отсечение и типичные паттерны — но всё это будет строиться на одном принципе: **описывайте мир, а не процедуру**.

## Часть II. Основы синтаксиса

### 7. Термы: четыре вида

Всё в Prolog — **терм**. Их четыре вида.

**Атомы** — простые имена, начинаются со строчной буквы:

```prolog
ivan
parent
hello_world
moscow
```

Можно в кавычках, если нужны пробелы или заглавные:
```prolog
'Hello, World'
'Иван Иванович'
```

**Числа** — целые и вещественные:

```prolog
42
-7
3.14
1e-3
```

**Переменные** — начинаются с заглавной буквы или `_`:

```prolog
X
Y
MyVar
_
```

`_` — **анонимная** переменная: каждое вхождение — новая переменная. Полезно, когда значение не нужно:

```prolog
has_child(X) :- parent(X, _).
```
*«X имеет ребёнка, если X — родитель кого-то (кого — неважно)»*.

**Составные термы** — функтор + аргументы в скобках:

```prolog
parent(ivan, alexey)
f(X, Y, Z)
point(3, 4)
list_of(a, b, c)
```

Функтор — это просто имя. `parent(ivan, alexey)` **не** «вызывает функцию parent» — это факт с двумя аргументами.

### 8. Унификация

Унификация — сердце Prolog. Это **сопоставление** двух термов с поиском подстановки, которая сделает их одинаковыми.

Правила унификации:
- Атом унифицируется сам с собой: `ivan = ivan`.
- Переменная унифицируется с **чем угодно**: `X = 42`, `X = parent(ivan, Y)`.
- Если переменная **уже связана**, она заменяется на значение: `X = 42, X = 42` — успех; `X = 42, X = 43` — провал.
- Составные термы унифицируются, если совпадают функторы, арности и все аргументы унифицируются.

```prolog
?- f(X, 2) = f(1, Y).
X = 1, Y = 2.
```

```prolog
?- f(X, X) = f(1, 2).
false.
```
*Нельзя, чтобы X был одновременно 1 и 2.*

```prolog
?- parent(X, Y) = parent(ivan, alexey).
X = ivan, Y = alexey.
```

**Ключевая идея:** `=` — это не «присваивание», а «унификация». `X = 42` не «кладёт 42 в X», а «говорит, что X и 42 — это одно и то же».

### 9. Запросы

В IDE запросы пишутся без `?-`, но с точкой в конце:

```prolog
parent(ivan, X).
```

Движок ответит:
```
X = alexey
── N решений ──
```

Если решений несколько (например, `parent(ivan, X)` даёт `alexey` и `maria`), `▶ Run` покажет все, а `⏩ First` — первое.

### 10. Факты и правила

**Факт** — предложение без тела:

```prolog
parent(ivan, alexey).
```

Читается: *«ivan — родитель alexey»* (истинно всегда).

**Правило** — с телом:

```prolog
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
```

Читается: *«X — дедушка/бабушка Z, если X — родитель Y и Y — родитель Z»*.

### 11. Порядок выполнения

Prolog доказывает цели **слева направо**. При неудаче **возвращается назад** (backtracking) и пробует следующий вариант.

```prolog
?- parent(ivan, X), parent(X, petr).
```

1. Доказать `parent(ivan, X)` → `X = alexey` (первый факт).
2. С `X = alexey` доказать `parent(alexey, petr)` → успех (есть такой факт).
3. Ответ: `X = alexey`.

Если бы `parent(alexey, petr)` не нашёлся, движок вернулся бы к шагу 1 и взял следующий `parent(ivan, X)` — `maria`. И снова проверил бы `parent(maria, petr)`.

### 12. Backtracking

Backtracking — это автоматический **перебор**. Когда Prolog не может доказать цель, он откатывается к последней точке выбора и пробует другой вариант.

```prolog
parent(ivan, alexey).
parent(ivan, maria).

?- parent(ivan, X).
X = alexey ;   ← пользователь нажимает "ещё"
X = maria.
```

Точка `;` означает «продолжить поиск». В IDE `▶ Run` находит все решения, `⏩ First` — только первое.

### 13. Арифметика

Арифметика — **отдельная** область в Prolog. Терм `2 + 3` — это **не** число `5`, а структура с функтором `+`:

```prolog
?- X = 2 + 3.
X = 2+3.        ← не 5!
```

Чтобы **вычислить**, нужен оператор `is`:

```prolog
?- X is 2 + 3.
X = 5.
```

`is` — это предикат: `Result is Expression`. Он вычисляет `Expression` и унифицирует с `Result`.

**Сравнение чисел:**

```prolog
X > Y       % больше
X < Y       % меньше
X >= Y      % больше или равно
X =< Y      % меньше или равно (обратите внимание на =<, не <=)
X =:= Y     % числовое равенство
X =\= Y     % числовое неравенство
```

Не путайте с `=`:

```prolog
?- 2 = 2.       true
?- 2 = 2.0.     false    ← разные термы
?- 2 =:= 2.0.   true     ← одинаковы как числа
```

### 14. Списки

Список — это либо пустой `[]`, либо cons-ячейка `[Head | Tail]`:

```prolog
[]
[1, 2, 3]
[a, b | Rest]
[H | T]
```

На самом деле `[1, 2, 3]` — синтаксический сахар для `'.'(1, '.'(2, '.'(3, [])))`. Но думать так не нужно: `[H | T]` — это **голова** `H` и **хвост** `T`.

Пример — длина списка:

```prolog
my_length([], 0).
my_length([_ | T], N) :-
    my_length(T, N1),
    N is N1 + 1.
```

Читается:
- *«длина пустого списка = 0»*.
- *«длина списка с головой и хвостом T = N, если длина T = N1 и N = N1 + 1»*.

Первый факт — база. Второе правило — шаг рекурсии. Это классический паттерн в Prolog.

### 15. Рекурсия

Рекурсия в Prolog — норма, а не экзотика. Любая структура (список, дерево, число) обходится рекурсивно:

```prolog
factorial(0, 1).
factorial(N, F) :-
    N > 0,
    N1 is N - 1,
    factorial(N1, F1),
    F is N * F1.
```

Читается: *«факториал 0 — 1; факториал N — F, если N > 0, N1 = N − 1, факториал N1 — F1, F = N × F1»*.

**Правило хорошего тона:** всегда ставьте базовый случай **первым**, а проверку `N > 0` — перед рекурсивным вызовом. Иначе `factorial(-1, F)` уйдёт в бесконечную рекурсию.

### 16. Хвостовая рекурсия (TCO)

Если рекурсивный вызов — **последняя цель** в теле правила, Prolog может выполнить его без роста стека (Tail Call Optimization):

```prolog
% Не хвостовая: рекурсивный вызов в середине
factorial(N, F) :-
    N > 0,
    N1 is N - 1,
    factorial(N1, F1),       ← не последняя
    F is N * F1.

% Хвостовая: рекурсивный вызов — последняя цель
factorial(N, F) :- factorial_acc(N, 1, F).
factorial_acc(0, Acc, Acc).
factorial_acc(N, Acc, F) :-
    N > 0,
    Acc1 is Acc * N,
    N1 is N - 1,
    factorial_acc(N1, Acc1, F).    ← последняя цель
```

Хвостовая версия использует **аккумулятор** (`Acc`) и не растёт по стеку. Для `factorial(10000, F)` это критично.

### 17. Отсечение `!`

Отсечение — управляющая конструкция. `!` **отменяет** все точки выбора, созданные с момента входа в текущий предикат:

```prolog
max(X, Y, X) :- X >= Y, !.
max(_, Y, Y).
```

Без `!` запрос `max(3, 5, M)`:
1. Пробует первое правило: `3 >= 5` — провал.
2. Пробует второе: `M = 5`. Успех.

Но что если `max(5, 3, M)`?
1. Первое правило: `5 >= 3` — успех, `M = 5`.
2. **Без `!`** движок запомнил, что можно попробовать второе правило. Пользователь может попросить «ещё» и получить `M = 3` — **неправильно**!

С `!` после `X >= Y`:
1. Первое правило: `5 >= 3` — успех, `!` отсекает второе правило, `M = 5`.
2. «Ещё» — нет решений. Правильно.

**Правило:** ставьте `!` **сразу после** проверки, которая делает остальные правила ненужными.

**Осторожно:** злоупотребление `!` скрывает альтернативы и делает программу нереляционной. Используйте только когда уверены.

### 18. Отрицание `\+`

`\+ Goal` — «Goal не доказуемо»:

```prolog
not_parent(X) :- \+ parent(X, _).
```

**Важно:** `\+` работает через **неудачу доказательства**, а не через «ложь в логическом смысле». Если переменные в `Goal` не связаны, `\+` может дать неожиданный результат. Всегда убедитесь, что переменные связаны до вызова `\+`.

### 19. If-then-else

```prolog
classify(X, positive) :- X > 0, !.
classify(X, negative) :- X < 0, !.
classify(_, zero).
```

Или через `->` (if-then-else):

```prolog
sign(X, S) :-
    ( X > 0 -> S = positive
    ; X < 0 -> S = negative
    ; S = zero
    ).
```

`Cond -> Then ; Else` — если `Cond` доказуемо, выполняется только `Then`, иначе только `Else`. Альтернативы внутри `Cond` отсекаются автоматически (как будто там стоит `!`).

### 20. Собираем всё вместе

Программа «семья»:

```prolog
parent(ivan, alexey).
parent(ivan, maria).
parent(alexey, petr).
parent(alexey, anna).
parent(maria, sergey).

grandparent(X, Z) :- parent(X, Y), parent(Y, Z).

sibling(X, Y) :-
    parent(P, X),
    parent(P, Y),
    X \= Y.

cousin(X, Y) :-
    parent(P1, X),
    parent(P2, Y),
    sibling(P1, P2).
```

Запросы:

```prolog
?- grandparent(ivan, X).
X = petr ;
X = anna ;
X = sergey.
```

```prolog
?- sibling(petr, X).
X = anna.
```

```prolog
?- cousin(petr, X).
X = sergey.
```

Каждое правило читается как английское предложение. Ни одного цикла, ни одного `if`. Только описание мира.

## Часть III. Пользовательские предикаты на Python

До сих пор мы описывали мир **только фактами и правилами Prolog**. Но есть задачи, где чистая логика бессильна: вызвать LLM, обратиться к базе данных, посчитать сложную формулу, отправить HTTP-запрос. Для этого в PyAgentProlog есть **Python-действия** — обычные Python-функции, подключённые к Prolog как предикаты.

### 23. Зачем это нужно

Логика и вычисления — разные вещи. Prolog хорошо описывает **отношения** (`X — родитель Y`, `X — дедушка Z`). Но у него нет доступа к внешнему миру:

- как спросить у ChatGPT «Столица Франции?»;
    
- как найти расстояние между двумя точками;
    
- как прочитать файл;
    
- как отправить email;
    
- как вызвать локальную модель.
    

Всё это — **действия**, которые делает Python. Идея простая: **описывайте мир на Prolog, а действия — на Python**.

```prolog

% Prolog описывает, что значит "близкий город"
near(City) :-
    city(City, X, Y),
    distance_to_target(X, Y, D),   ← Python-действие
    D < 5.0.
```

``` Python
# Python-действие
@simple_action('distance_to_target', 3, output_arg=2)
def distance_to_target(x, y, context):
    tx = context.get('target_x', 10.0)
    ty = context.get('target_y', 5.0)
    return ((x - tx) ** 2 + (y - ty) ** 2) ** 0.5
```
Prolog описывает **логику**, Python — **вычисление**. Это и есть гибридный подход — «нейро-символический» в широком смысле.

### 24. Три вида декораторов

PyAgentProlog предоставляет три декоратора из `prolog.actions`. Все они:

- превращают обычную Python-функцию в предикат Prolog;
    
- принимают аргументы, автоматически конвертированные из термов Prolog в Python-значения;
    
- передают `context` — словарь внешних ресурсов;
    
- регистрируются в `Agent` автоматически.
    

Разница — в том, **сколько решений** даёт функция.

#### 24.1. `simple_action` — одно решение

```python

from prolog.actions import simple_action
@simple_action('double', 2, output_arg=1)
def double(x, context):
    return x * 2
```

- **Сигнатура:** `@simple_action(name, arity, output_arg=-1, description=None)`
    
- **Параметры:**
    
    - `name='double'` — имя предиката в Prolog.
        
    - `arity=2` — число аргументов в Prolog (`double/2`).
        
    - `output_arg=1` — индекс выходного аргумента (0-based). Остальные — входные.
        
    - `description` — описание (по умолчанию — docstring функции).
        
- **Входные аргументы** должны быть **конкретизированы** до вызова (не быть свободными переменными). Иначе действие не сработает.
    
- **Возвращает** одно значение → оно унифицируется с `output_arg`.
    
- Если функция вернула `None` → предикат считается **провалившимся**.
    

В Prolog:

```prolog
?- double(21, X).
X = 42.
```

С несколькими входами:

```python
@simple_action('distance', 3, output_arg=2)
def distance(x1, y1, context):
    return ((x1 - 10.0) ** 2 + (y1 - 5.0) ** 2) ** 0.5
```

```prolog
?- distance(13.0, 9.0, D).
D = 5.0.
```

#### 24.2. `effector_action` — side effect, без возврата

```python
from prolog.actions import effector_action
@effector_action('log_msg', 1)
def log_msg(msg, context):
    print(f"[LOG] {msg}")
```

- **Сигнатура:** `@effector_action(name, arity, description=None)`
    
- **Все аргументы** — входные. Должны быть конкретизированы.
    
- **Возвращает** `None`. Побочный эффект — печать, запись в файл, отправка в API, изменение `context`.
    
- Предикат **успешен**, если функция выполнилась без исключений.
    
- Если внутри — исключение, предикат **провалится**.
    

В Prolog:

```prolog
run :-
    log_msg('start'),
    do_work,
    log_msg('done').
```

Запрос `run.` → в консоли IDE `[LOG] start`, `[LOG] done`, в Результате `── 1 решение(й) ──` (успех без переменных).

#### 24.3. `generator_action` — много решений

```python
from prolog.actions import generator_action
@generator_action('count_to', 2, output_arg=1)
def count_to(n, context):
    for i in range(1, n + 1):
        yield i
```

- **Сигнатура:** `@generator_action(name, arity, output_arg=-1, description=None)`
    
- Функция — **генератор** (`yield` вместо `return`).
    
- Каждое значение из итератора → **отдельное решение**.
    
- Порядок решений — порядок `yield`.
    

В Prolog:

```prolog
?- count_to(3, X).
X = 1 ;
X = 2 ;
X = 3.
```

`▶ Run` покажет все решения, `⏩ First` — только `X = 1`.

### 25. Конвертация значений Prolog ↔ Python

Когда действие вызывается, аргументы Prolog конвертируются в Python-значения. Обратно — результат конвертируется в терм Prolog.

**Prolog → Python:**

|Prolog|Python|
|---|---|
|`Number(42)`|`42`|
|`Number(3.14)`|`3.14`|
|`Term('ivan')` (атом)|`'ivan'`|
|`Term('"hello"')` (строка в кавычках)|`'hello'`|
|Список `[1, 2, 3]`|`[1, 2, 3]`|
|`Variable('X')` (свободная)|`None`|
|Составной терм `f(a, b)`|`'f(a, b)'` (строка)|

**Python → Prolog:**

|Python|Prolog|
|---|---|
|`42` / `3.14`|`Number(42)` / `Number(3.14)`|
|`True` / `False`|`Term('true')` / `Term('false')`|
|`'hello'`|`Term('"hello"')` (строка в кавычках)|
|`[1, 2, 3]`|Prolog-список `[1, 2, 3]`|
|`None`|Пустой список `[]`|
|`{'a': 1}`|Список пар `[a-1]`|

**Важное следствие:** входные аргументы должны быть **конкретизированы**. Если в Prolog передать `double(X, Y)` со свободными `X, Y`, действие вернёт `[]` — провал. Всегда проверяйте, что переменные связаны перед вызовом действия:

```prolog
?- X = 21, double(X, Y).
X = 21, Y = 42.
```

### 26. `context` — внешние ресурсы

Все действия получают **второй невидимый аргумент** — `context`. Это словарь, в котором живут внешние ресурсы: LLM-клиент, соединение с БД, API-ключи, конфигурация.

```python
@simple_action('ask_llm', 2, output_arg=1)
def ask_llm(prompt, context):
    llm = context.get('llm')
    if llm is None:
        return "(no llm configured)"
    return llm.invoke(prompt).content
```

`context` **не приходит из Prolog** — это глобальный словарь, привязанный к `Agent`. Заполняется так:

```python
from langchain_openai import ChatOpenAI
agent.context['llm'] = ChatOpenAI(model='gpt-4o-mini')
agent.context['api_key'] = 'sk-...'
agent.context['db'] = my_database_connection
```

Затем в Prolog:

prolog

ask(P, R) :- ask_llm(P, R).

```prolog
?- ask('Столица Франции?', R).
R = 'Париж'.
```

**Зачем `context`, а не глобальные переменные?** Потому что у разных `Agent` могут быть **разные** LLM/БД/ключи. `context` изолирует их — как замыкание в Python.

### 27. Регистрация действий

Есть **три способа** подключить действие к `Agent`.

#### 27.1. Одиночная функция

```python
agent.register_action(double)
agent.register_action(log_msg)
agent.register_action(count_to)
```

Каждая функция с декоратором должна быть зарегистрирована **явно**.

#### 27.2. Модуль целиком

```python
import my_actions
agent.register_action_module(my_actions)
```

`register_action_module` просканирует все атрибуты модуля, найдёт функции с `_agent_action=True` (это ставит любой из трёх декораторов) и зарегистрирует их.

#### 27.3. Автоматически — в PyAgentProlog IDE

В IDE **не нужно** ничего регистрировать вручную. Просто положите `my_actions.py` рядом с `kb.pl`:

```text
my_project/
├── kb.pl
└── my_actions.py
```

`my_actions.py`:

```python
from prolog.actions import simple_action, effector_action
@simple_action('double', 2, output_arg=1)
def double(x, context):
    return x * 2
@effector_action('log_msg', 1)
def log_msg(msg, context):

```

**Что **не** нужно делать:**

❌ **Не** вызывайте `agent.register_action(...)` внутри `my_actions.py` — IDE сделает это сама.

❌ **Не** импортируйте `Agent` и не создавайте его вручную.

❌ **Не** делайте `sys.path.insert` — IDE уже добавила папку проекта в `sys.path`, соседние модули импортируются свободно:

### 28. Обработка ошибок в действиях

Поведение по умолчанию: **любое исключение внутри действия → предикат проваливается** (`fail`). Это удобно для «тихого» отлова, но иногда скрывает ошибки.

Пример:

```python
@simple_action('divide', 3, output_arg=2)
def divide(x, y, context):
    return x / y
```

```prolog
?- divide(10, 0, R).
false.           ← не ошибка, а просто fail
```

Если хотите **явную** ошибку, поднимите `PrologError`:

```python
from prolog.predicates import PrologError
@simple_action('divide', 3, output_arg=2)
def divide(x, y, context):
    if y == 0:
        raise PrologError('evaluation_error', 'zero_divisor')
    return x / y
```

Теперь `divide(10, 0, R)` вернёт `✗ evaluation_error: zero_divisor`.

**Правило:** молчаливый `fail` — для «нет результата». `PrologError` — для настоящей ошибки (деление на ноль, неверный тип, недоступный сервис).

### 29. Программирование агентов

`Agent` — это класс из `prolog.agent`, который объединяет:

- **программу** Prolog (факты и правила);
    
- **действия** (Python-предикаты);
    
- **context** (внешние ресурсы).
    

Простой агент:

```python
from prolog.agent import Agent
from prolog.actions import simple_action, effector_action
# Программа
agent = Agent("""
start :-
    log_msg('Agent started'),
    double(21, X),
    log_msg(X).
""")
# Действия
@effector_action('log_msg', 1)
def log_msg(msg, context):
    print(f"[AGENT] {msg}")
@simple_action('double', 2, output_arg=1)
def double(x, context):
    return x * 2
# Регистрация
agent.register_action(log_msg)
agent.register_action(double)
# Запуск
result = agent.query("start.")
print(result)
# [AGENT] Agent started
# [AGENT] 42
```

#### 30.6. Встроенные предикаты агента

`Agent` автоматически регистрирует два полезных предиката:

**`set_state/1`** — заменить все факты с тем же функтором/арностью одним новым:

```prolog
set_state(mode(search)).
```

Если в базе было `mode(idle).`, оно удаляется. Остаётся `mode(search).`.

**`update_state/1`** — добавить факт, не удаляя старые:

```prolog
update_state(observed(bravo, search, 10.0, 5.0, 17)).
```

Теперь в базе есть запись `observed(...)`, старые `observed(...)` сохранены.

Это классический паттерн для агентов: `set_state` — «установить текущий режим», `update_state` — «добавить наблюдение».

**Что произошло:** Prolog описал структуру («для каждого промпта — свой ответ»), Python выполнил действие (реальный вызов LLM). Логика и вычисление разделены — как и должно быть в гибридной системе.

### 32. Legacy: `agent_action` и прямое программирование предикатов

Если нужен полный контроль над сигнатурой предиката (`goal, database, subst, depth`), есть legacy-декоратор `agent_action`:

```python
from prolog.agent import agent_action
@agent_action('my_pred', 1, description="...", action_type="generic")
def my_pred(goal, database, subst, depth):
    # goal.arguments[0] — аргумент Prolog
    arg = goal.arguments[0].substitute(subst)
    # ... ваша логика
    yield subst.copy()
```

Это **низкоуровневый** API — вы получаете управление над подстановкой, глубиной, точкой backtracking. Нужен редко; в 95% случаев хватает `simple_action` / `effector_action` / `generator_action`.

**Не путайте:**

- `agent_action` — низкоуровневый, вы **сами** пишете всю логику предиката.
    
- `simple_action` / `effector_action` / `generator_action` — высокоуровневые, вы пишете **обычную Python-функцию**, декоратор делает из неё предикат.
    

### 33. Лучшие практики

1. **Только декораторы + функции** в `my_actions.py`, без побочных эффектов на уровне модуля (никаких `print` при импорте, никаких сетевых вызовов).
    
2. **`context`** — единственный канал к внешним ресурсам. Не используйте глобальные переменные.
    
3. **Входные аргументы** должны быть конкретизированы — проверяйте `X` перед `double(X, Y)`.
    
4. **`None` от `simple_action`** — это провал. Используйте осознанно.
    
5. **`PrologError`** — для настоящих ошибок. Иначе — молчаливый `fail`.
    
6. **Одна функция — одна ответственность.** Не делайте `simple_action` с пятью ветвлениями.
    
7. **Именование:** имя Prolog-предиката — snake_case, как в Python. `distance_to_target`, не `DistanceToTarget`.
    
8. **Документируйте** через `description=` или docstring — это видно в `⚡ Зарегистрированные действия` в IDE.
    
9. **Реимпорт** — по `mtime_ns + size`. Если правите файл и не видите изменений, нажмите 🔄 Перезагрузить в IDE.

## Часть IV. Практические паттерны

### 34. Рекурсивный обход списка

Классический паттерн из двух предложений:

```prolog
predicate([], BaseCase).
predicate([H | T], Result) :-
    do_something(H, ...),
    predicate(T, ...).
```

Пример — сумма элементов:

```prolog
sum([], 0).
sum([H | T], S) :-
    sum(T, S1),
    S is H + S1.
```

Хвостовая версия:

```prolog
sum(L, S) :- sum_acc(L, 0, S).
sum_acc([], Acc, Acc).
sum_acc([H | T], Acc, S) :-
    Acc1 is Acc + H,
    sum_acc(T, Acc1, S).
```

### 35. Генерация и проверка

Prolog позволяет **генерировать** решения, а потом **отбирать** подходящие:

```prolog
% Все пары (X, Y) из списка, где X < Y
pairs([], []).
pairs([H | T], Result) :- ...
```

Другой пример — генератор чисел:

```prolog
between_gen(Low, High, Low) :- Low =< High.
between_gen(Low, High, X) :-
    Low < High,
    Low1 is Low + 1,
    between_gen(Low1, High, X).
```

```prolog
?- between_gen(1, 5, X).
X = 1 ; X = 2 ; X = 3 ; X = 4 ; X = 5.
```

### 36. `findall` — собрать все решения

```prolog
findall(Template, Goal, List).
```

Собирает все `Template`, для которых `Goal` доказуемо, в список `List`:

```prolog
?- findall(X, parent(ivan, X), Children).
Children = [alexey, maria].
```

```prolog
?- findall(X-Y, parent(X, Y), Pairs).
Pairs = [ivan-alexey, ivan-maria, alexey-petr, ...].
```

`-` внутри терма — это просто функтор. `X-Y` — пара.

### 37. `assert` / `retract` — динамическая база

Иногда нужно **изменять** базу знаний во время выполнения:

```prolog
?- assertz(fact(5)).
true.

?- fact(X).
X = 1 ; X = 2 ; X = 3 ; X = 4 ; X = 5.
```

- `assertz` — добавить в конец.
- `asserta` — добавить в начало.
- `retract` — удалить первое совпадение.
- `retractall` — удалить все.

Осторожно: `assert`/`retract` перестраивают индекс. В цикле это заметно медленно.

### 38. Работа с термами

Prolog умеет разбирать термы на части:

```prolog
?- functor(parent(ivan, alexey), F, A).
F = parent, A = 2.

?- arg(1, parent(ivan, alexey), X).
X = ivan.

?- parent(ivan, alexey) =.. L.
L = [parent, ivan, alexey].
```

Это полезно для метапрограммирования (генерации правил, обработки выражений).

### 39. Отладка

**Write** — простейший инструмент:

```prolog
debug(X) :- write('X = '), write(X), nl.
```

```prolog
run :- parent(ivan, X), debug(X), fail.
```

`fail` в конце гарантирует, что движок будет перебирать **все** решения.

**Trace** в IDE — следующий шаг. Поставьте breakpoint на предикат, который «не работает», — и посмотрите, какие аргументы приходят.

**`📚 KB`** — проверьте, как правило **распарсилось**. Часто ошибки в скобках или приоритетах операторов видны именно там.

## Часть IV. Частые ошибки новичков

### 40. Ошибки в синтаксисе

**Забыли точку в конце.** `parent(ivan, alexey)` — не предложение. Нужно `parent(ivan, alexey).`.

**Забыли запятую между целями.** `parent(X, Y) parent(Y, Z)` — синтаксическая ошибка. Нужно `parent(X, Y), parent(Y, Z)`.

**Забыли скобки вокруг `->`.** `( Cond -> Then ; Else )` — если убрать внешние скобки, приоритеты съедут.

**Путаница `=` и `is`.** `X = 2 + 3` не вычисляет. Нужно `X is 2 + 3`.

### 41. Логические ошибки

**Забыли базовый случай.** `length([], 0). length([_|T], N) :- ...` — без первого факта `length([], 0)` уйдёт в бесконечную рекурсию.

**Неправильный порядок целей.** `length(X, N), N > 0` — сначала `length` генерирует бесконечное число решений, потом проверяет `N > 0`. Пользователь не дождётся. Правильно: `N > 0, length(X, N)` — сначала конкретизируем `N`.

**Не связали переменную перед `\+`.** `\+ parent(X, Y)` с несвязанными `X` и `Y` — «есть ли хоть какой-то родитель?». Не то, что вы, возможно, имели в виду.

**Забыли `!` там, где нужно.** `max(X, Y, X) :- X >= Y.` без `!` — если `max(5, 3, M)`, пользователь может получить и `M = 5` (правильно), и `M = 3` (неправильно).

**Поставили `!` не там.** `p :- a, !, b.` — `!` отсекает альтернативы `a`, но не `p` целиком. Если хотите «если `a` успешно — только это правило», ставьте `!` после `a`, но до любых других целей, которые могут дать альтернативы.
### 42. Ошибки в действиях

**Забыли зарегистрировать.** `agent.register_action(double)` — без него предикат не появится. В IDE с `my_actions.py` регистрация автоматическая, но при явном создании `Agent` — нужна.

**Забыли положить в context.** `context['llm']` — если `llm` не задан, действие вернёт `(no llm)` или упадёт. Проверяйте через 🔌 Контекст.

**Передали свободную переменную.** `double(X, Y)` с несвязанным `X` → `fail`. Всегда `X = 21, double(X, Y)`.

**Исключение вместо PrologError.** `x / 0` без проверки → молчаливый `fail`. Хотите явную ошибку — `raise PrologError(...)`.

**Забыли про реимпорт.** Изменили `my_actions.py`, не нажали 🔄 — старое поведение.
### 43. Ошибки эффективности

**Не хвостовая рекурсия на больших данных.** `sum([H|T], S) :- sum(T, S1), S is H + S1.` — стек растёт. Используйте аккумулятор.

**`assert` в цикле.** Каждый `assert` перестраивает индекс. Если нужно много фактов — `assertz` пачкой или через `agent.add_facts()`.

**`findall` на большом результате.** Собирает **все** решения в память. Если решение одно — используйте `once` или `call_cleanup`.

**Нет индекса по первому аргументу.** `parent(X, Y) :- ...` — все правила в одном bucket'е. `parent(ivan, Y) :- ...` — только `ivan` в быстром bucket'е.

## Шпаргалка

```prolog
% Факт
parent(ivan, alexey).

% Правило
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).

% Списки
[H | T]             % голова H, хвост T
[]                  % пустой список
[a, b, c]           % [a, b, c]

% Арифметика
X is 2 + 3          % вычислить
X =:= Y             % числовое равенство

% Сравнение
X = Y               % унификация
X == Y              % идентичность (без связывания)
X \= Y              % не унифицируется

% Управление
!                   % отсечение
\+ Goal             % отрицание
( Cond -> Then ; Else )

% Мета
findall(T, G, L)    % все T, где G, в список L
call(G)             % вызвать G как цель
once(G)             % первое решение G

% Динамическая база
assertz(fact(...))  % добавить
retract(fact(...))  % удалить первое
```

Удачи! Откройте IDE, загрузите пример `family`, введите `grandparent(ivan, X).` и нажмите **▶ Run**. Дальше — экспериментируйте.
