## Что такое «человек-в-цикле»?

В современных ИИ-агентах «человек-в-цикле» (human-in-the-loop, HITL) означает, что в процессе автоматического выполнения задачи предусмотрены точки взаимодействия с человеком: запрос подтверждения, уточнение данных, выбор варианта, приостановка до получения ответа и т.п. Такой подход повышает надёжность, доверие и позволяет решать задачи, где полная автоматизация невозможна.

## Реализация в langgraph

LangGraph — фреймворк для построения графовых агентов на основе LangChain. В нём HITL реализуется через специальные механизмы прерывания (interrupt) и возобновления (resume). Обычно:

- Агент строится как граф состояний (узлы и рёбра).
- В определённом узле вызывается функция, которая может запросить ввод человека. При этом выполнение графа приостанавливается, а текущее состояние сохраняется.
- После получения ответа от человека граф возобновляется с того же места, используя сохранённое состояние.

Примерный код на langgraph:

```python
from langgraph.graph import StateGraph, END
from langgraph.checkpoint import MemorySaver

# Определяем состояние
class State(TypedDict):
    query: str
    human_feedback: str

# Узел, запрашивающий подтверждение
def ask_human(state: State):
    # Здесь можно отправить сообщение человеку через внешний канал
    # и приостановить выполнение
    return {"human_feedback": "ожидание..."}

# Узел обработки ответа
def process(state: State):
    feedback = state["human_feedback"]
    # ... обработка
    return {"result": feedback}

graph = StateGraph(State)
graph.add_node("ask", ask_human)
graph.add_node("process", process)
graph.add_edge("ask", "process")
graph.set_entry_point("ask")

# Используем чекпоинт для сохранения состояния
memory = MemorySaver()
app = graph.compile(checkpointer=memory)

# Запуск с возможностью прерывания
config = {"configurable": {"thread_id": "1"}}
events = app.stream(initial_state, config, interrupt_before=["ask"])
# Далее обрабатываем прерывание и возобновляем
```

Таким образом, разработчик должен явно управлять графом, точками прерывания и возобновления.

## Реализация в PyAgentProlog

Фреймворк PyAgentProlog (построенный на интерпретаторе Prolog) предлагает иной, более декларативный подход. Логика агента описывается правилами Prolog, а взаимодействие с человеком реализуется через **пользовательские предикаты (действия)**, которые естественным образом приостанавливают выполнение до получения ввода. Состояние агента хранится в базе знаний в виде фактов, поэтому его не нужно специально сохранять — оно уже там.

### Как это работает

1. **Действие** (например, `ask_user/2`) определяется на Python и регистрируется в агенте. Оно может выводить вопрос и ожидать ввод от человека.
2. В Prolog-правиле вызывается это действие. Поскольку выполнение Prolog последовательное, агент «зависает» на этом вызове до тех пор, пока действие не вернёт результат.
3. Результат унифицируется с переменной и используется далее в правилах.
4. После завершения правила состояние агента (факты) уже обновлено, и при следующем запуске (например, после перезапуска программы) можно продолжить с того же места, так как факты сохраняются в базе знаний.

Имеется интеграция с пакетом Gradio: [[Инструкция по программированию ИИ-агентов с интерфейсом Gradio]]
### Пример

Создадим действие `ask_user/2`, которое выводит вопрос и возвращает ответ:

```python
from prolog.agent import simple_action

@simple_action('ask_user', 2, output_arg=1)
def ask_user(question, context):
    """
    ask_user(+Question, -Answer)
    Задаёт вопрос пользователю и возвращает ответ.
    """
    print(f"[Агент спрашивает]: {question}")
    answer = input("Ваш ответ: ").strip()
    return answer
```

В Prolog-программе агента используем это действие:

```prolog
:- dynamic step/1.

start :-
    write('Начинаем процесс...'), nl,
    ask_user('Подтвердите начало операции (да/нет)', Answer),
    handle_answer(Answer).

handle_answer('да') :-
    write('Операция запущена.'), nl,
    do_work.
handle_answer('нет') :-
    write('Операция отменена.'), nl,
    fail.  % или завершить

do_work :-
    % ... какие-то действия
    ask_user('Продолжить?', Cont),
    ( Cont == 'да' -> do_work ; write('Завершено.') ).
```

При выполнении запроса `start.` агент остановится на `ask_user`, дождётся ввода, а затем продолжит. Никаких дополнительных механизмов для прерывания и возобновления не требуется — это естественное поведение интерпретатора.

### Сохранение состояния между сеансами

Если нужно сохранить состояние агента между запусками программы, можно сериализовать базу знаний. В PyAgentProlog это можно сделать, например, сохраняя все факты в файл и загружая их при инициализации. Но даже без этого, в рамках одного сеанса состояние хранится автоматически.

## Сравнение подходов

| Аспект                        | LangGraph                                                                                         | PyAgentProlog                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Модель выполнения**         | Граф состояний с явными узлами и переходами                                                       | Логический вывод на основе правил (поиск с возвратами)                                          |
| **Реализация HITL**           | Требует определения точек прерывания, сохранения состояния через чекпоинты, ручного возобновления | Естественная приостановка на вызове действия, ожидающего ввод; состояние хранится в базе знаний |
| **Сложность кода**            | Необходимо настроить граф, чекпоинты, обработать прерывания                                       | Достаточно определить простое Python-действие и вызвать его в правиле                           |
| **Гибкость**                  | Легко комбинировать с другими узлами, интеграция с LangChain                                      | Легко изменять логику, добавляя новые правила и факты; вся мощь Prolog                          |
| **Требования к разработчику** | Знание концепций графов, LangChain                                                                | Понимание основ Prolog                                                                          |
| **Сохранение прогресса**      | Через чекпоинты (можно хранить в БД)                                                              | Автоматически в фактах; можно сериализовать базу знаний                                         |

## Выводы

В PyAgentProlog принцип «человек-в-цикле» реализуется гораздо более декларативно и с меньшим количеством инфраструктурного кода, чем в langgraph. Это достигается за счёт использования логической парадигмы Prolog, где ожидание ввода — это просто ещё одно действие, а состояние автоматически сохраняется в фактах. LangGraph, в свою очередь, предлагает более явное управление графом, что может быть удобно в сложных сценариях с множеством параллельных ветвей.

Выбор между ними зависит от предпочтений разработчика и специфики задачи: если вам близок декларативный стиль и вы готовы писать на Prolog, proagent даст более лаконичное решение для HITL. Если вы работаете в экосистеме LangChain и нуждаетесь в тонком контроле над графом, langGraph будет более подходящим инструментом.
