Данная инструкция предназначена для разработчиков, создающих собственные действия (actions) для агентов на базе фреймворка **PyAgentProlog**. Действия — это Python-функции, которые вызываются из Prolog-программы как встроенные предикаты. Они реализуют всю «внешнюю» функциональность агента: взаимодействие с пользователем, вызов языковых моделей, обращение к базам данных, управление эффекторами и т.д.

Благодаря специальным декораторам, разработчику не нужно вникать в детали взаимодействия с Prolog (унификация, подстановки, списки решений). Достаточно написать обычную Python-функцию с понятными параметрами и возвращаемым значением.

## 1. Основные декораторы для действий

В фреймворке предусмотрено три основных декоратора, покрывающих наиболее частые сценарии:

- **`@simple_action`** – для действий, которые принимают входные аргументы и возвращают **одно значение**. Это значение будет унифицировано с указанным выходным аргументом предиката.
- **`@effector_action`** – для действий, которые только выполняют побочный эффект и **не возвращают значения** (например, вывод на экран, отправка команды). Все аргументы считаются входными.
- **`@generator_action`** – для действий, которые могут породить **несколько альтернативных решений** (например, перебор значений из диапазона). Функция должна быть генератором (использовать `yield`).

Все декораторы автоматически регистрируют функцию как Prolog-предикат с указанным именем и арностью, а также добавляют метаинформацию (описание, тип), которая затем доступна через `agent.list_actions()`.

## 2. Декоратор `@simple_action`

### Синтаксис

```python
@simple_action(name, arity, output_arg=-1, description=None)
def my_action(..., context):
    # ... тело функции
    return result
```

### Параметры

- `name` (str) – имя предиката в Prolog (например, `'read_input'`).
- `arity` (int) – общее количество аргументов предиката.
- `output_arg` (int) – **индекс выходного аргумента** (начиная с 0). Именно в этот аргумент будет подставлен результат, возвращаемый функцией. Если `output_arg = -1`, считается, что выходного аргумента нет (что эквивалентно `@effector_action`, но лучше использовать соответствующий декоратор).
- `description` (str, optional) – описание действия. Если не указано, используется docstring функции.

### Сигнатура функции

Функция принимает **все входные аргументы** (кроме выходного) в том же порядке, что и в Prolog, и обязательный параметр `context` (см. раздел 6). Входные аргументы автоматически преобразуются из Prolog-термов в Python-объекты (числа, строки, списки и т.д.). Выходной аргумент в списке параметров отсутствует.

Функция должна вернуть некоторое значение (или `None` в случае неудачи). Это значение будет преобразовано в Prolog-терм и унифицировано с выходным аргументом.

### Пример

```python
@simple_action('read_input', 1, output_arg=0)
def read_input(context):
    """
    read_input(-Text)
    Считывает строку из стандартного ввода и возвращает её.
    """
    line = input(">> ").strip()
    return line
```

В Prolog этот предикат будет вызываться как `read_input(Text)`. При вызове переменная `Text` унифицируется с введённой строкой.

### Пример с несколькими входными аргументами

```python
@simple_action('add', 3, output_arg=2)
def add(a, b, context):
    """
    add(+A, +B, -Result)
    Возвращает сумму A и B.
    """
    return a + b
```

В Prolog: `add(5, 3, X)` успешно унифицирует `X` с `8`. Аргументы `a` и `b` будут числами.

## 3. Декоратор `@effector_action`

### Синтаксис

```python
@effector_action(name, arity, description=None)
def my_action(..., context):
    # ... тело функции
    # ничего не возвращает (или возвращает неважно что)
```

### Параметры

- `name` (str) – имя предиката.
- `arity` (int) – арность.
- `description` (str, optional) – описание.

### Сигнатура функции

Функция принимает **все аргументы** (в порядке объявления) как входные, плюс `context`. Все аргументы должны быть конкретизированы (не переменные). Возвращаемое значение игнорируется. Если функция выполнилась без исключений, предикат считается успешным.

### Пример

```python
@effector_action('print_message', 1)
def print_message(msg, context):
    """
    print_message(+Message)
    Выводит сообщение на экран.
    """
    print(f"[Агент]: {msg}")
```

В Prolog: `print_message('Hello')` выведет сообщение и завершится успешно.

## 4. Декоратор `@generator_action`

### Синтаксис

```python
@generator_action(name, arity, output_arg=-1, description=None)
def my_action(..., context):
    for value in ...:
        yield value
```

### Параметры

Аналогично `@simple_action`.

### Сигнатура функции

Функция принимает входные аргументы (кроме выходного) и `context`. Она должна быть **генератором** (содержать `yield`). Каждое `yield` порождает отдельное решение, в котором выходной аргумент унифицируется с очередным значением.

### Пример

```python
@generator_action('between', 3, output_arg=2)
def between_gen(low, high, context):
    """
    between(+Low, +High, -Value)
    Генерирует все целые числа от Low до High включительно.
    """
    for i in range(low, high + 1):
        yield i
```

В Prolog: `between(1, 3, X)` последовательно выдаст `X = 1`, `X = 2`, `X = 3` при возвратах (backtracking).

## 5. Преобразование типов между Prolog и Python

Фреймворк автоматически преобразует аргументы, переданные из Prolog, в Python-объекты и обратно. Преобразование выполняется функциями `prolog_to_python` и `python_to_prolog`. Таблица соответствия:

| Prolog-терм                      | Python-объект               |
|----------------------------------|------------------------------|
| Число (целое или с плавающей точкой) | `int` / `float`           |
| Строка в двойных кавычках (`"text"`) | `str` (без кавычек)       |
| Атом (без кавычек)               | `str`                        |
| Список (`[a, b, c]`)             | `list` Python                |
| Пустой список (`[]`)              | Пустой список `[]`           |
| Составной терм (`f(1,2)`)         | `str` (упрощённое представление) |
| Словарь (переданный из Python как список пар `-`) | `dict` (если словарь был передан из Python, он восстановится) |

Обратное преобразование (из Python в Prolog):
- `int`/`float` → `Number`
- `str` → атом в кавычках (например, `"hello"`)
- `list` → прологовский список через конс-ячейки
- `dict` → список пар `-(Key, Value)`
- `None` → пустой список `[]`
- прочие типы → строковое представление в кавычках

**Важно**: при передаче составных термов (не списков) из Prolog в Python они преобразуются в строку. Если вам нужно работать со структурой, лучше передавать её как список или явно разбирать строку.

## 6. Контекст агента

Все действия получают параметр `context` – это словарь, который был передан при создании агента (`Agent(..., context=my_context)`). В нём можно хранить любые внешние ресурсы, необходимые действиям: клиенты LLM, соединения с базами данных, конфигурационные параметры и т.п.

```python
@simple_action('ask_llm', 2, output_arg=1)
def ask_llm(prompt, context):
    client = context['llm_client']
    return client.generate(prompt)
```

Контекст доступен **только для чтения** (хотя технически его можно изменять, но это не рекомендуется, лучше использовать состояние агента через Prolog).

## 7. Регистрация действий

После определения всех действий их необходимо зарегистрировать в экземпляре агента. Это можно сделать двумя способами:

### Регистрация одного действия

```python
agent.register_action(read_input)
agent.register_action(print_message)
```

### Регистрация всех действий из модуля

```python
import sys
agent.register_action_module(sys.modules[__name__])
```

Этот метод автоматически находит все функции в указанном модуле, у которых есть атрибут `_agent_action` (добавляемый декораторами), и регистрирует их.

После регистрации можно просмотреть список доступных действий:

```python
for act in agent.list_actions():
    print(f"{act['name']}/{act['arity']}: {act['description']} ({act['type']})")
```

## 8. Встроенные предикаты для управления состоянием

Фреймворк предоставляет два встроенных действия, которые автоматически регистрируются в каждом агенте:

- **`set_state(Term)`** – заменяет **все** факты с тем же функтором и арностью, что и `Term`, на новый факт `Term`. Требует, чтобы `Term` был конкретизирован (не содержал переменных). Идеально для хранения одиночного значения (например, текущей фазы).
- **`update_state(Term)`** – добавляет `Term` как новый факт, не удаляя старые. Подходит для накопления информации (история, инвентарь).

Пример использования в Prolog:

```prolog
:- dynamic state/2.
:- dynamic memory/1.

init :-
    set_state(state(phase, init)),
    set_state(memory([])).

step :-
    state(phase, init),
    read_input(Action),
    set_state(memory(Action)),
    set_state(state(phase, working)).
```

Обратите внимание, что для работы с динамическими предикатами их необходимо объявить директивой `:- dynamic`.

## 9. Обработка ошибок и неудач

- Если действие должно сигнализировать о **неудаче** (например, не удалось прочитать данные), в `@simple_action` и `@generator_action` верните `None` (или ничего не yield'те в генераторе). В `@effector_action` можно выбросить исключение или ничего не делать – исключение будет перехвачено и приведёт к неудаче.
- Любое необработанное исключение внутри действия также приводит к неудаче (пустому списку решений). При включённом `DEBUG` в `agent.py` информация об исключении выводится в консоль.
- Если входной аргумент, который должен быть конкретизирован (входной), оказывается свободной переменной, действие автоматически завершается неудачей.

## 10. Пример: агент с действиями

Приведём полный пример агента, использующего все три типа действий. Этот код является частью файла `example_proagent.py`.

```python
import sys
from proalog.agent import Agent, simple_action, effector_action

@simple_action('read_input', 1, output_arg=0)
def read_input(context):
    line = input(">> ").strip()
    return line

@effector_action('print_message', 1)
def print_message(msg, context):
    print(f"[Агент]: {msg}")

@simple_action('llm_echo', 2, output_arg=1)
def llm_echo(prompt, context):
    return f"Эхо: {prompt}"

AGENT_PROGRAM = """
:- dynamic state/2.
:- dynamic memory/1.

init :- set_state(state(phase, init)), set_state(memory([])).

step :- state(phase, Phase), handle_phase(Phase, NextPhase),
        set_state(state(phase, NextPhase)), continue(NextPhase).

continue(final) :- !.
continue(_) :- step.

handle_phase(init, working) :-
    print_message('Агент инициализирован. Введите действие:'),
    read_input(Action),
    set_state(memory(Action)),
    print_message('Действие запомнено.').

handle_phase(working, final) :-
    memory(LastAction),
    print_message('Последнее действие:'),
    print_message(LastAction),
    llm_echo(LastAction, Analysis),
    print_message('LLM ответила:'),
    print_message(Analysis),
    print_message('Завершаю работу.').

handle_phase(final, final) :-
    print_message('Агент уже завершил работу.').

run :- init, step.
"""

def main():
    agent = Agent(AGENT_PROGRAM, context={'llm': None})
    agent.register_action_module(sys.modules[__name__])

    print("Зарегистрированные действия:")
    for act in agent.list_actions():
        print(f"  {act['name']}/{act['arity']}: {act['description']}")

    print("\nЗапуск агента (запрос 'run.')")
    agent.query('run.')

if __name__ == "__main__":
    main()
```

## 11. Отладка действий

- Установите `DEBUG = True` в начале файла `agent.py` (или в своём коде, если экспортируете эту переменную). Тогда в консоль будут выводиться сообщения о вызове каждого действия и об исключениях.
- Используйте параметр `with_explanation=True` в методе `query`, чтобы получить дерево доказательства Prolog. Это поможет понять, почему некоторые цели не достигаются.
- Для тестирования отдельных действий можно вызывать их напрямую как обычные Python-функции, передавая фиктивный контекст.

## 12. Расширение возможностей

Если стандартных декораторов недостаточно, вы всегда можете использовать базовый декоратор `@agent_action`, который даёт полный доступ к механизмам Prolog (параметры `goal`, `database`, `subst`, `depth`). Однако в большинстве случаев новые декораторы покрывают все потребности.

## 13. Заключение

Разработчик сосредотачивается на логике своего действия, а фреймворк берёт на себя всю сложность взаимодействия с Prolog. Используйте эту инструкцию как справочник при создании собственных агентов.
