### 1. Введение

**PyAgentProlog** — фреймворк для создания интеллектуальных агентов, сочетающий логическое программирование на Prolog и гибкость Python.  
Ключевая идея: **картина мира** (модель среды, знания агента) хранится и обрабатывается на Prolog, а взаимодействие с внешним миром (сенсоры, эффекторы, вызовы LLM, API) реализуется на Python.  
Такой гибридный подход позволяет агенту:

- рассуждать дедуктивно и индуктивно, используя унификацию, backtracking и правила;
- динамически изменять свою базу знаний (добавлять/удалять факты и правила);
- выполнять сложные запросы с переменными и условиями;
- легко интегрироваться с любыми Python-библиотеками.

### 2. Основные компоненты архитектуры

Архитектура PyAgentProlog состоит из следующих взаимосвязанных модулей:

| Компонент | Назначение |
|-----------|-------------|
| **`Agent`** | Главный интерфейс для разработчика. Управляет базой знаний, регистрирует Python-действия, выполняет запросы. |
| **`Database`** | Хранит правила и факты Prolog. Обеспечивает индексацию, динамическое изменение (add/retract), вызов встроенных предикатов. |
| **`Solver`** | Обёртка над интерпретатором. Преобразует запросы в решения, поддерживает трассировку (объяснение вывода). |
| **`Interpreter`** | Итеративный алгоритм поиска с возвратами, оптимизация хвостовых вызовов, поддержка cut (`!`), repeat, дизъюнкции, условного оператора. |
| **`Parser`** | Преобразует текст Prolog во внутреннее представление (термы, правила). Удаляет комментарии, обрабатывает операторы и списки. |
| **Python-действия** | Функции, декорированные `@simple_action`, `@effector_action` или `@generator_action`. Вызываются из Prolog как встроенные предикаты. |
| **Контекст (`context`)** | Словарь, передаваемый в каждое действие. Содержит внешние ресурсы (LLM-клиенты, БД, API). |

### 3. Картина мира: представление знаний на Prolog

Картина мира агента — это набор фактов и правил, хранящийся в **базе знаний** (объект `Database`).  
Факты описывают текущее состояние среды:  
```prolog
lights([(kitchen, off), (living_room, on), (bedroom, off)]).
temperature(kitchen, 22.5).
```
Правила выражают зависимости и логику поведения:
```prolog
dark(Room) :- light(Room, off).
needs_light(Room) :- dark(Room), occupied(Room).
```

#### Рекомендация: единый корневой факт
Для обеспечения **целостности и атомарности** обновлений рекомендуется хранить всё состояние агента в одном или нескольких «корневых» фактах (например, `world/1`).  
Это позволяет заменить картину мира целиком за один шаг, избегая промежуточных противоречивых состояний.

### 4. Обновление картины мира: `set_state` и `update_state`

Вместо низкоуровневых `asserta`/`retract` фреймворк предоставляет два агент-ориентированных предиката:

- **`set_state(+Fact)`** – заменяет **все** факты с тем же функтором и арностью, что и `Fact`, на новый факт `Fact`.  
  *Пример:*  
  ```prolog
  set_state(lights([(kitchen, on), (bedroom, off)])).
  ```
  Атомарная операция, гарантирует согласованность.

- **`update_state(+Fact)`** – добавляет `Fact` в базу знаний, не удаляя старые факты.  
  Полезен для накопления истории или логов.

Оба предиката требуют, чтобы `Fact` был полностью конкретизирован (не содержал переменных).  
Они уже встроены в `Agent` и доступны в любой Prolog-программе без дополнительной регистрации.

### 5. Сенсоры и эффекторы: Python-действия

Взаимодействие с реальным миром реализуется через **Python-функции**, которые регистрируются как Prolog-предикаты.  
Для этого используются три декоратора:

| Декоратор | Назначение | Пример Prolog-вызова |
|-----------|------------|----------------------|
| `@simple_action(name, arity, output_arg)` | Принимает входные аргументы, возвращает одно значение (унифицируется с выходным аргументом). | `read_input(Text)` |
| `@effector_action(name, arity)` | Выполняет побочный эффект, ничего не возвращает. Все аргументы входные. | `turn_light(room, on)` |
| `@generator_action(name, arity, output_arg)` | Генерирует последовательность значений (yield). Каждое значение даёт отдельное решение. | `between(1,10,X)` |

**Преобразование типов** выполняется автоматически:
- Prolog → Python: числа, строки, списки, атомы.
- Python → Prolog: int/float → `Number`, str → атом в кавычках, list → Prolog-список, dict → список пар `-(Key,Value)`.

**Доступ к контексту** – каждая функция может принимать параметр `context`, через который передаётся словарь, заданный при создании агента:
```python
@simple_action('ask_llm', 2, output_arg=1)
def ask_llm(prompt, context):
    llm = context.get('llm_client')
    return llm.generate(prompt)
```

### 6. Поток выполнения запроса

1. **Пользователь (или другой компонент)** вызывает метод `agent.query("цель.")`.
2. **Парсер** преобразует строку запроса в объект `Term`.
3. **Солвер** передаёт запрос интерпретатору (`Database._solve_iterative`).
4. **Интерпретатор** итеративно обрабатывает цели:
   - Если цель – встроенный предикат (например, `is`, `member`), вызывает его реализацию.
   - Если цель – пользовательский предикат, ищет правила в индексе, переименовывает переменные, пытается унифицировать голову.
   - При успешной унификации формирует новый кадр с целями тела правила.
   - Поддерживает backtracking, отсечение (`!`), хвостовую рекурсию.
5. **Python-действия** (зарегистрированные через декораторы) вызываются точно так же, как встроенные предикаты. Они получают конкретизированные аргументы, выполняют Python-код и возвращают результат (или `None`/генератор).
6. **Обновление базы знаний** происходит через вызовы `set_state`/`update_state` внутри Prolog-правил или через Python-действия, которые могут напрямую обращаться к `database.add_rule` и т.д.
7. **Решения** собираются и преобразуются в удобный Python-формат (словари переменная→значение). При необходимости возвращается дерево трассировки (`with_explanation=True`).

### 7. Интеграция с внешней средой через контекст

Поле `context` в классе `Agent` (и `Database`) предназначено для передачи внешних ресурсов, которые могут понадобиться Python-действиям:

- Клиенты LLM (OpenAI, LangChain, HuggingFace)
- Подключения к базам данных
- Очереди сообщений
- Объекты для доступа к аппаратным датчикам и эффекторам

Контекст доступен в любом действии через именованный параметр `context`.  
Это позволяет сохранять состояние между вызовами (например, сессию пользователя) и использовать сложные сервисы без глобальных переменных.

### 8. Пример архитектуры в действии (управление освещением)

Ниже показана упрощённая архитектура агента, управляющего светом в комнатах:

```prolog
% Картина мира – один факт
lights([(kitchen, off), (bedroom, on)]).

% Запрос состояния
light(Room, State) :- lights(L), member((Room, State), L).

% Действие переключения
toggle(Room) :-
    light(Room, State),
    ( State = on -> New = off ; New = on ),
    set_light(Room, New).

set_light(Room, NewState) :-
    lights(OldL),
    update_list(OldL, Room, NewState, NewL),
    set_state(lights(NewL)),           % атомарное обновление картины мира
    physical_turn_light(Room, NewState). % вызов Python-эффектора
```

Python-эффектор:

```python
@effector_action('physical_turn_light', 2)
def physical_turn_light(room, state, context=None):
    # Отправить команду реальному устройству
    send_command(room, state)
```

**Поток**:
- Пользователь вызывает `agent.query("toggle(kitchen).")`
- Prolog находит правило `toggle`, получает текущее состояние через `light/2`, вычисляет новое состояние.
- `set_light/2` строит новый список, вызывает `set_state(lights(...))` (замена факта) и затем `physical_turn_light/2`.
- Python-функция отправляет команду.
- База знаний теперь содержит обновлённый факт `lights`.

### 9. Преимущества и ограничения подхода

**Преимущества**:
- **Декларативность** – картина мира описывается фактами и правилами, легко читается и модифицируется.
- **Атомарные обновления** – `set_state` исключает промежуточные противоречия.
- **Мощный логический вывод** – унификация, backtracking, рекурсия.
- **Гибкость Python** – доступ к любой экосистеме библиотек.
- **Объяснимость** – встроенная трассировка показывает цепочку вывода.

**Ограничения**:
- Индексация правил только по первому аргументу (может быть медленно при очень больших базах).
- Нет встроенной поддержки неопределённости, вероятностей.
- Ограниченное подмножество Prolog (отсутствуют DCG, полноценный I/O, модули).

### 10. Заключение

Архитектура агента в PyAgentProlog строит мост между декларативным представлением знаний (Prolog) и императивной логикой взаимодействия с внешним миром (Python).  
**Картина мира** как динамический набор фактов/правил управляется через специальные предикаты `set_state`/`update_state`, что обеспечивает целостность и атомарность изменений.  
**Python-действия** (сенсоры и эффекторы) интегрируются через простые декораторы, получая доступ к контексту агента.  
Такой подход идеально подходит для создания адаптивных агентов, способных рассуждать, планировать и обучаться, работая в реальной среде.
